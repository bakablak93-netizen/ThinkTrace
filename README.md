# ThinkTrace AI

Прототип для IT FEST 2026 (направление «Minds and Machines in Rethinking Learning»).

Студент решает линейное уравнение **по шагам**. Система проверяет каждый шаг, определяет
тип ошибки и ведёт наводящими вопросами, **не выдавая решение**. После решения даёт
похожую задачу без подсказок (задача переноса), чтобы проверить понимание.

**Принцип:** математику и диагностику делает код (SymPy). LLM только формулирует текст
(подсказка по готовому ID ошибки, разбор неизвестной ошибки, текст отчёта). У каждой
LLM-функции есть шаблонный fallback, поэтому демо работает без интернета.

## Структура

```
backend/
  requirements.txt, pytest.ini
  thinktrace/
    expr.py         дерево выражения, сохраняющее запись студента; перевод в SymPy
    parser.py       строка -> Equation (свой парсер, без eval)
    verifier.py     equivalent(prev, new), is_solved(eq)  (SymPy)
    bugs/catalog.py каталог типовых ошибок (5 типов)
    bank.py         банк задач: 15 уравнений A/B/C + близнецы
    diagnose.py     поиск ошибки по каталогу
    hints.py        Hint Ladder (уровни 1-4)
    problems.py     генераторы задач и задач переноса
    events.py       журнал событий (Thinking Trace)
    tutor.py        логика сессии (состояние восстанавливается из журнала)
    report.py       отчёт по сессии
    ratelimit.py    лимиты запросов для публичного демо
    llm.py          LLMClient: OpenAIClient + TemplateClient, валидация JSON, guard
    prompts/system.md  системный промпт и правила для модели
    i18n.py         тексты ru/kk/en
    db.py           SQLite (stdlib sqlite3)
    api.py          FastAPI; раздаёт и собранный фронтенд
  tests/
frontend/           React + Vite + TypeScript
  src/i18n/         ru.ts, kk.ts, en.ts
Dockerfile          один образ: API + собранный фронтенд
render.yaml         конфиг деплоя на Render (Blueprint)
```

## Локальный запуск

Backend (Python 3.11+):

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn thinktrace.api:create_app --factory --reload --port 8000
```

Frontend (Node 18+), во втором терминале:

```bash
cd frontend
npm install
npm run dev
```

Откройте http://localhost:5173. Vite проксирует `/api` на `localhost:8000`.

Вариант «как на хостинге», один процесс: выполните `npm run build` в `frontend/` и
запустите только backend. Тогда фронтенд откроется на http://localhost:8000.

Тесты:

```bash
cd backend && pytest -q
```

cyrillic-ext с `unicode-range` (`frontend/src/styles/fonts.css`). В JetBrains Mono нет
казахских букв Ә Ғ Қ Ң Ұ Һ, поэтому вторым в стеке стоит Inter: в Chromium проверено,
что эти буквы рисует Inter, а не системный шрифт. Формулы шагов рисует KaTeX.

**Фон (BackgroundFX):** один `<canvas aria-hidden="true">` под контентом, WebGL1 без
библиотек. Два прохода: шейдер поля (градиент и свечение за курсором) и частицы
(`gl.POINTS`, аддитивное смешивание), физика частиц на CPU. Частиц 110–320 по площади
экрана (не больше 160 на экранах уже 600 px). Цикл `requestAnimationFrame` всегда один,
он останавливается при скрытой вкладке; DPR не выше 2; обрабатываются
`webglcontextlost`/`restored`. При `prefers-reduced-motion` рисуется один статичный кадр.
Без WebGL canvas скрывается и остаётся CSS-градиент.

```ts
const fx = useFx();              // из FxProvider (frontend/src/fx/FxProvider.tsx)
fx.pulse(x, y, kind);            // координаты в пикселях окна
fx.pulseFrom(element, kind);     // от центра элемента
```

| kind | Когда | Эффект |
|---|---|---|
| `tap` | клик по любой кнопке | маленькая нейтральная волна |
| `key` | ввод в поле шага | микро-вспышка в поле |
| `ok` | верный шаг | частицы ~0.3 с стягиваются к шагу, затем мятная волна |
| `err` | ошибка | дрожание частиц ~0.5 с и коралловая волна |
| `ai` | показана подсказка | голубая волна от карточки подсказки |
| `solved` | задача решена | сильное стягивание, янтарная и мятная волны, лёгкий оттенок фона |

Оттенок фона ослаблен по сравнению с прототипом (0.07 вместо 0.35): иначе в пике волны
текст прямо на фоне терял контраст ниже 4.5:1.

**Отключение:** `VITE_FX=off` при сборке (`VITE_FX=off npm run build`, или build arg
`VITE_FX=off` для Docker) — canvas не создаётся, фон CSS-градиентом. Удобно для жюри,
слабых машин и тестов.

Тесты фронтенда: `cd frontend && npm test` (vitest + jsdom).

## Банк задач и типы ошибок

### Типы ошибок (`backend/thinktrace/bugs/catalog.py`)

Все типы ошибок распознаются кодом, без LLM. Для каждого типа задано правило, по которому
из предыдущего шага строятся все возможные ошибочные варианты; шаг студента сравнивается
с ними в два уровня: точное совпадение даёт уверенность 0.9, совпадение только по корню
даёт 0.5. Если подходит несколько типов, уверенность делится между ними.

| Код | Ошибка | Пример |
|---|---|---|
| `DIST_FIRST_ONLY` | множитель умножен только на одно слагаемое скобки | 2(x + 3) → 2x + 3 |
| `DIST_SIGN` | минус перед скобкой применён не ко всем слагаемым | −(x − 3) → −x − 3; −2(x − 4) → −2x − 8 |
| `SIGN_ON_TRANSFER` | перенос через «=» без смены знака | 2x + 3 = 11 → 2x = 11 + 3 |
| `DIVIDE_ONE_SIDE` | разделена только одна часть | 3x = 12 → x = 12 |
| `COMBINE_UNLIKE` | сложены слагаемое с x и число | 3x + 2 → 5x (или 5) |

У каждого типа есть шаблонные подсказки уровней 1–3, а у новых типов (`DIST_SIGN`,
`COMBINE_UNLIKE`) ещё и свой шаблон уровня 4. Шаблоны уровней 1–3 в тестах проходят через
guard на всех задачах банка: ни один не раскрывает ответ. При множителе −1 ошибка
считается ошибкой знака (`DIST_SIGN`), а не неполным раскрытием.

### Банк задач (`backend/thinktrace/bank.py`)

15 линейных уравнений для 8–9 класса, у каждого есть близнец: та же структура и сложность,
другие числа и другое решение (всего 30 записей). Близнец служит финальной задачей без
подсказок и парой для пред- и пост-теста. Поля: `id`, уравнение, решение, уровень, теги
(типичные ошибки), `twin_id`.

| Уровень | Что внутри | Задачи |
|---|---|---|
| A | ax + b = c | A1–A5 |
| B | скобки, x в одной части (B1 = стартовая задача 2(x + 3) = 14) | B1–B5 |
| C | x в обеих частях, скобки, отрицательные множители; C5 с дробным решением x = 4/3 | C1–C5 |

Задачи и решения пишет команда, а проверяет ядро. Тесты `tests/test_bank.py` проверяют:
- SymPy находит единственное решение и оно совпадает с полем `solution`;
- задача и близнец совпадают по структуре (операции, знаки, скобки), но не по решению;
- задача соответствует своему уровню;
- каждый тег — ошибка, которая реально может случиться на пути решения этой задачи.

LLM задачи и ответы не создаёт. Корень 0 исключён: при x = 0 неверный шаг может сохранить
решение и пройти проверку как верный.

В интерфейсе на стартовом экране есть кнопки «Уровень A/B/C», а после решения задачи из
банка — «Следующая задача» (следующая по кругу того же уровня). «Демо-задача» по-прежнему
открывает 2(x + 3) = 14. API: `POST /api/sessions/{id}/problems` принимает необязательные
`level` (A/B/C) и `after` (id предыдущей задачи); в ответе добавлены `bank_id` и `level`.
Для задачи из банка финальная задача — её близнец; для сгенерированных задач всё как раньше.

## Индекс самостоятельности

Показывается в отчёте, считается только из журнала событий (`backend/thinktrace/report.py`):

```
A (подсказки) = max(0, 1 − H/4)    H — подсказки, которые студент запросил сам
                                    (автоматические подсказки после ошибки не считаются:
                                    ошибка уже учтена в B)
B (попытки)   = верные шаги / все проверенные шаги в основных задачах
C (перенос)   = 1 решена без ошибок, 0.5 решена с ошибками, 0 начата и не решена

I = 100 × (0.4·A + 0.3·B + 0.3·C)
Перенос не начат: I = 100 × (0.4·A + 0.3·B) / 0.7, индекс помечен как неполный.
```

Не входят: «Найди ошибку» и «Объясни своими словами». Веса выбраны командой как
разумные по смыслу, на данных они не калиброваны. Индекс описывает ход сессии и не
является оценкой способностей.

## Режим «Найди ошибку»

На стартовом экране есть кнопка «Найди ошибку». Система показывает решение задачи
`a(x + b) = cx + d` из 5 шагов с одной ошибкой из каталога. Студент выбирает шаг с
ошибкой и тип ошибки (верный вариант и отвлекающие варианты из каталога). Решение
генерирует код (`backend/thinktrace/find_error.py`), без LLM. Каждое решение проверяет то же ядро:
ровно один неэквивалентный переход, и диагноз этого перехода совпадает с выбранной ошибкой.
Подсказки идут по той же лестнице: уровень 1 общий, 2 указывает шаг, 3 даёт правило, 4
показывает верный вариант после двух неверных ответов. Ответы пишутся в журнал и
показываются в отчёте.

## Как используется ИИ

Математику, проверку шагов и тип ошибки определяет код (SymPy + каталог ошибок).
Языковая модель (OpenAI) **только формулирует текст**:

1. подсказки уровней 1–3 по ID найденной ошибки, на языке студента (ru/kk/en);
2. разбор ошибки вне каталога (UNKNOWN): вероятная причина в осторожной форме, без ответа.
3. «Объясни своими словами»: после исправленной ошибки студент может (необязательно,
   до 300 символов) объяснить, что было не так. Модель отвечает по формуле «что верно /
   на что обратить внимание», без оценки и без влияния на результаты. Без LLM студент
   видит правило из каталога со словами «сравни со своим объяснением». Промпт лежит в
   `prompts/explain.md`, текст студента передаётся модели как данные, guard тот же.
   Сам текст объяснения не сохраняется, в журнал пишутся только длина и источник ответа.

Остальное всегда шаблоны: неоднозначный диагноз (несколько кандидатов), уровень 4
(показывает верный шаг, его считает код) и подсказки «что делать дальше».

Как защищён ответ модели (`backend/thinktrace/llm.py`):

- в модель уходят только условие, шаги студента, уровень, язык и ID/описание ошибки;
  ник, ID сессии и другие данные не отправляются (это проверяет тест);
- правила для модели лежат в `backend/thinktrace/prompts/system.md`;
- ответ должен быть JSON `{"hint": "..."}` (JSON Schema), не длиннее 400 символов;
  таймаут 5 секунд, без повторов, до 300 токенов ответа;
- guard (`hints.leaks_answer`) проверяет каждый ответ модели: если там `x = <корень>`
  или сам корень, которого нет в условии и шагах, подставляется шаблон;
- при любой проблеме (нет ключа, таймаут, ошибка API, невалидный JSON, сработал guard)
  подставляется шаблон, и урок продолжается;
- в журнал событий пишется `source: llm | template` и причина подстановки шаблона, а в
  интерфейсе рядом с подсказкой видна пометка «подсказка ИИ» или «шаблонная подсказка».

Новый провайдер добавляется отдельным классом-наследником `ProviderClient` и записью в
`PROVIDERS` в `llm.py`.

## Защита публичного демо

Эндпоинты, которые вызывают LLM (отправка шага, подсказка) и отчёт, ограничены: не больше `RATE_LIMIT_PER_SESSION` запросов на сессию и
`RATE_LIMIT_PER_DAY` на весь сервис в сутки. Сверх лимита сервер отвечает 429, а
интерфейс показывает понятное сообщение. Ограничения:

- счётчики живут в памяти процесса и обнуляются при перезапуске;
- новая сессия получает новый лимит на сессию, от этого защищает только суточный лимит;
- **поставьте лимит расходов в кабинете OpenAI**. Это единственная надёжная защита от счёта.

## Данные

- Хранится только анонимный ник, без ФИО, почты, IP и данных устройства.
- «Удалить мои данные»: при старте сессия получает токен (в БД хранится только его
  SHA-256). `DELETE /api/sessions/{id}` с заголовком `X-Session-Token` удаляет сессию,
  её задачи и события, а ник, если у него не осталось других сессий. Без своего токена
  удалить сессию нельзя (403). Токен живёт только в памяти вкладки: после перезагрузки
  страницы удалить эту сессию уже нельзя, но на бесплатном хостинге данные всё равно
  стираются при перезапуске.
- Диагноз вероятностный. Это помечено в интерфейсе, а кнопка «Не согласен с оценкой» сохраняет событие.
- По одной ошибке система не делает выводов о способностях человека.

**Важно для хостинга.** На бесплатном тарифе Render диск временный: база SQLite
**обнуляется при каждом деплое, перезапуске и засыпании сервиса**, а засыпание
наступает после 15 минут без запросов. Для демо это нормально: сессию проходят и
смотрят отчёт за один заход. Не рассчитывайте, что данные сохранятся до следующего дня.

Как хранить данные постоянно: постоянный диск у Render есть только на платных тарифах
(цену проверь у провайдера). В `render.yaml` нужно сменить `plan: free` на платный
тариф и добавить:

```yaml
    disk:
      name: data
      mountPath: /app/data
      sizeGB: 1
```

`DATABASE_PATH` в образе уже указывает в `/app/data`. По документации Render, с диском
пропадают деплои без простоя (сервис недоступен несколько секунд при обновлении), и
сервис нельзя масштабировать больше чем на один экземпляр.

## Деплой

### Какой хостинг выбрать

Проверено по официальной документации 27.11.2026. Условия меняются, поэтому перед
деплоем проверьте ещё раз.

| | **Render** (рекомендую) | **Koyeb** |
|---|---|---|
| Бесплатно | веб-сервис 0.1 CPU / 512 MB, 750 ч в месяц на workspace | 1 бесплатный инстанс на организацию: 0.1 vCPU / 512 MB / 2 GB SSD |
| Сон | после 15 мин без трафика, просыпается около минуты | после 1 ч без трафика (scale-to-zero, в статусе preview) |
| Автодеплой из GitHub | да, по `render.yaml` (`autoDeployTrigger: commit`) | да, но по документации **только для репозиториев GitHub-организации**; для личного репозитория проверь у провайдера |
| Конфиг в репо | `render.yaml` уже есть | нет, настройка в панели |
| Постоянный диск | только на платных тарифах | на бесплатном нельзя; volumes в preview |
| Банковская карта | проверь у провайдера | в FAQ сказано, что карта требуется (холд $29); относится ли это к бесплатному тарифу, не указано |
| Регион | по умолчанию Oregon, есть Frankfurt | бесплатный: Frankfurt или Washington |

Почему Render: конфиг уже в репозитории, автодеплой с личного репо описан в документации,
сон после 15 минут не критичен, если открыть ссылку за минуту до показа.

**Не проверено и стоит уточнить у провайдера:** документация Render не говорит прямо,
можно ли бесплатный сервис собирать из Dockerfile. Если при создании Blueprint Render
откажет из-за `plan: free`, напишите мне.

Hugging Face Spaces не подходит: по их документации Docker-Space требует платного плана.

### Шаги для Render (нужен только браузер и GitHub)

Названия кнопок я брал из документации, в интерфейсе они могут немного отличаться.

1. **Ветка `main`.** Деплой настроен на ветку `main`. Слейте в неё pull request с этой
   работой: на GitHub откройте вкладку **Pull requests**, затем PR → **Merge pull request**.
2. Зайдите на https://render.com, выберите **Sign up / Log in with GitHub**.
3. В панели Render: **New** → **Blueprint**.
4. Подключите GitHub, если Render попросит, и дайте доступ к репозиторию `ThinkTrace`.
   Достаточно доступа только к нему.
5. Выберите репозиторий `ThinkTrace` и ветку **`main`**. Render найдёт `render.yaml` и
   покажет сервис `thinktrace` (тариф Free). Нажмите **Apply** (или **Deploy Blueprint**).
6. Подождите окончания сборки: первая занимает несколько минут, лог виден в панели.
   Когда статус станет **Live**, вверху страницы сервиса появится адрес вида
   `https://thinktrace-….onrender.com`. Это и есть постоянная ссылка.
7. Проверка: откройте `<адрес>/health`. Должно показать `{"status":"ok"}`. Потом откройте сам адрес.
8. Подключение ИИ: сервис `thinktrace` → вкладка **Environment** → **Add Environment
   Variable**, три штуки:

   | Key | Value |
   |---|---|
   | `LLM_PROVIDER` | `openai` |
   | `LLM_API_KEY` | ваш ключ OpenAI (ключ создаётся в кабинете OpenAI, раздел API keys) |
   | `LLM_MODEL` | id модели, доступной в вашем аккаунте OpenAI |

   Сохраните (**Save Changes**, или **Save, rebuild, and deploy**, если Render предложит).
   Ключ вводится только в этом поле: не в коде, не в `render.yaml`, не в чатах.
   `RATE_LIMIT_PER_SESSION` и `RATE_LIMIT_PER_DAY` уже заданы из `render.yaml`.
   Проверка: решите демо-задачу с ошибкой `2x+3=14`. Рядом с подсказкой должна быть пометка
   «подсказка ИИ». Если видите «шаблонная подсказка», значит переменные не заданы, ключ
   неверный или модель не ответила за 5 секунд. Это видно в логах сервиса (**Logs**,
   строки `LLM fallback to template: <причина>`).
9. Дальше всё автоматически: каждый push или merge в `main` запускает новую сборку и деплой.

Перед показом жюри откройте `<адрес>/health` и подождите ответа (около минуты, если сервис спал).
