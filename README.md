# ThinkTrace AI

Прототип для IT FEST 2026 (направление «Minds and Machines in Rethinking Learning»).

Студент решает линейное уравнение **по шагам**. Система проверяет каждый шаг, определяет
тип ошибки и ведёт наводящими вопросами, **не выдавая решение**. После решения даёт
похожую задачу без подсказок (задача переноса), чтобы проверить понимание.

**Принцип:** математику и диагностику делает код (SymPy). LLM только формулирует текст
(подсказка по готовому ID ошибки, разбор неизвестной ошибки, текст отчёта). У каждой
LLM-функции есть шаблонный fallback, поэтому демо работает без интернета.
Сейчас (этап 1) LLM не подключён, все тексты берутся из шаблонов.

## Структура

```
backend/
  requirements.txt, pytest.ini
  thinktrace/
    expr.py         дерево выражения, сохраняющее запись студента; перевод в SymPy
    parser.py       строка -> Equation (свой парсер, без eval)
    verifier.py     equivalent(prev, new), is_solved(eq)  (SymPy)
    bugs/catalog.py каталог типовых ошибок
    diagnose.py     поиск ошибки по каталогу
    hints.py        Hint Ladder (уровни 1-4)
    problems.py     генераторы задач и задач переноса
    events.py       журнал событий (Thinking Trace)
    tutor.py        логика сессии (состояние восстанавливается из журнала)
    report.py       отчёт по сессии
    ratelimit.py    лимиты запросов для публичного демо
    i18n.py         тексты ru/kk/en
    db.py           SQLite (stdlib sqlite3)
    api.py          FastAPI; раздаёт и собранный фронтенд
  tests/
frontend/           React + Vite + TypeScript
  src/i18n/         ru.ts, kk.ts, en.ts
Dockerfile          один образ: API + собранный фронтенд
render.yaml         конфиг деплоя на Render (Blueprint)
```

## Локальный запуск

Backend (Python 3.11+):

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn thinktrace.api:create_app --factory --reload --port 8000
```

Frontend (Node 18+), во втором терминале:

```bash
cd frontend
npm install
npm run dev
```

Откройте http://localhost:5173. Vite проксирует `/api` на `localhost:8000`.

Вариант «как на хостинге», один процесс: выполните `npm run build` в `frontend/` и
запустите только backend. Тогда фронтенд откроется на http://localhost:8000.

Тесты:

```bash
cd backend && pytest -q
```

## Конфигурация и секреты

- Локально: скопируйте `.env.example` в `.env` в корне репозитория. `.env` указан в `.gitignore`.
- На хостинге: **никаких файлов с секретами**. Все значения задаются как переменные
  окружения в панели хостинга (см. «Деплой»).
- Без `LLM_API_KEY` всё работает на шаблонах. Сейчас LLM-переменные кодом ещё не
  используются (этап 2).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DATABASE_PATH` | `thinktrace.sqlite3` (в Docker `/app/data/thinktrace.sqlite3`) | файл SQLite |
| `RATE_LIMIT_PER_SESSION` | `300` | запросов на одну сессию к шагам, подсказкам и отчёту |
| `RATE_LIMIT_PER_DAY` | `5000` | тех же запросов на весь сервис за сутки (UTC) |
| `LLM_PROVIDER`, `LLM_API_KEY`, `LLM_MODEL` | пусто | этап 2 |
| `STATIC_DIR` | `frontend/dist` | откуда раздавать собранный фронтенд |
| `FRONTEND_ORIGIN` | `http://localhost:5173` | CORS, нужен только если фронтенд на другом адресе |
| `PORT` | `10000` в Docker | порт; хостинг может задать свой |

## Защита публичного демо

Эндпоинты, которые на этапе 2 будут вызывать LLM (отправка шага, подсказка, отчёт),
ограничены: не больше `RATE_LIMIT_PER_SESSION` запросов на сессию и
`RATE_LIMIT_PER_DAY` на весь сервис в сутки. Сверх лимита сервер отвечает 429, а
интерфейс показывает понятное сообщение. Ограничения:

- счётчики живут в памяти процесса и обнуляются при перезапуске;
- новая сессия получает новый лимит на сессию, от этого защищает только суточный лимит;
- когда появится реальный LLM-ключ, **поставьте лимит расходов в кабинете провайдера**.
  Это единственная надёжная защита от счёта.

## Данные

- Хранится только анонимный ник, без ФИО, почты, IP и данных устройства.
- Эндпоинт полного удаления данных: этап 2.
- Диагноз вероятностный. Это помечено в интерфейсе, а кнопка «Не согласен с оценкой» сохраняет событие.
- По одной ошибке система не делает выводов о способностях человека.

**Важно для хостинга.** На бесплатном тарифе Render диск временный: база SQLite
**обнуляется при каждом деплое, перезапуске и засыпании сервиса**, а засыпание
наступает после 15 минут без запросов. Для демо это нормально: сессию проходят и
смотрят отчёт за один заход. Не рассчитывайте, что данные сохранятся до следующего дня.

Как хранить данные постоянно: постоянный диск у Render есть только на платных тарифах
(цену проверь у провайдера). В `render.yaml` нужно сменить `plan: free` на платный
тариф и добавить:

```yaml
    disk:
      name: data
      mountPath: /app/data
      sizeGB: 1
```

`DATABASE_PATH` в образе уже указывает в `/app/data`. По документации Render, с диском
пропадают деплои без простоя (сервис недоступен несколько секунд при обновлении), и
сервис нельзя масштабировать больше чем на один экземпляр.

## Деплой

### Какой хостинг выбрать

Проверено по официальной документации 27.11.2026. Условия меняются, поэтому перед
деплоем проверьте ещё раз.

| | **Render** (рекомендую) | **Koyeb** |
|---|---|---|
| Бесплатно | веб-сервис 0.1 CPU / 512 MB, 750 ч в месяц на workspace | 1 бесплатный инстанс на организацию: 0.1 vCPU / 512 MB / 2 GB SSD |
| Сон | после 15 мин без трафика, просыпается около минуты | после 1 ч без трафика (scale-to-zero, в статусе preview) |
| Автодеплой из GitHub | да, по `render.yaml` (`autoDeployTrigger: commit`) | да, но по документации **только для репозиториев GitHub-организации**; для личного репозитория проверь у провайдера |
| Конфиг в репо | `render.yaml` уже есть | нет, настройка в панели |
| Постоянный диск | только на платных тарифах | на бесплатном нельзя; volumes в preview |
| Банковская карта | проверь у провайдера | в FAQ сказано, что карта требуется (холд $29); относится ли это к бесплатному тарифу, не указано |
| Регион | по умолчанию Oregon, есть Frankfurt | бесплатный: Frankfurt или Washington |

Почему Render: конфиг уже в репозитории, автодеплой с личного репо описан в документации,
сон после 15 минут не критичен, если открыть ссылку за минуту до показа.

**Не проверено и стоит уточнить у провайдера:** документация Render не говорит прямо,
можно ли бесплатный сервис собирать из Dockerfile. Если при создании Blueprint Render
откажет из-за `plan: free`, напишите мне.

Hugging Face Spaces не подходит: по их документации Docker-Space требует платного плана.

### Шаги для Render (нужен только браузер и GitHub)

Названия кнопок я брал из документации, в интерфейсе они могут немного отличаться.

1. **Ветка `main`.** Деплой настроен на ветку `main`. Слейте в неё pull request с этой
   работой: на GitHub откройте вкладку **Pull requests**, затем PR → **Merge pull request**.
2. Зайдите на https://render.com, выберите **Sign up / Log in with GitHub**.
3. В панели Render: **New** → **Blueprint**.
4. Подключите GitHub, если Render попросит, и дайте доступ к репозиторию `ThinkTrace`.
   Достаточно доступа только к нему.
5. Выберите репозиторий `ThinkTrace` и ветку **`main`**. Render найдёт `render.yaml` и
   покажет сервис `thinktrace` (тариф Free). Нажмите **Apply** (или **Deploy Blueprint**).
6. Подождите окончания сборки: первая занимает несколько минут, лог виден в панели.
   Когда статус станет **Live**, вверху страницы сервиса появится адрес вида
   `https://thinktrace-….onrender.com`. Это и есть постоянная ссылка.
7. Проверка: откройте `<адрес>/health`. Должно показать `{"status":"ok"}`. Потом откройте сам адрес.
8. Переменные окружения: сервис → **Environment**. `RATE_LIMIT_PER_SESSION` и
   `RATE_LIMIT_PER_DAY` уже заданы из `render.yaml`. Когда будет готов этап 2, добавьте
   здесь `LLM_PROVIDER`, `LLM_API_KEY`, `LLM_MODEL`. Ключ вводится только в этом поле,
   ни в коде, ни в чатах.
9. Дальше всё автоматически: каждый push или merge в `main` запускает новую сборку и деплой.

Перед показом жюри откройте `<адрес>/health` и подождите ответа (около минуты, если сервис спал).
